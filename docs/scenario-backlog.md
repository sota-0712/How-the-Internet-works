# シナリオ候補・アイデア置き場

「ここがいまいちピンとこない」「これはアプリで見られたら分かりそう」と思ったことを、思いついたときに気軽に書き足す場所です。
整理されていなくて構いません。一行メモだけでも OK です。

候補がある程度育ったら、次サイクルで扱うシナリオを選び、BDD の Discovery（例を出し合って具体化する作業）にかけます。

## 使い方

1. 思いついたら「受信箱」に一行で書く（日付があると後で振り返りやすい）
2. 少し考えが進んだら、下のテンプレートで「シナリオ候補」に移す
3. サイクルで扱うと決めたら「採用済み」に移し、どのサイクルで扱ったかを書く
4. やらないと決めたものは消さずに「見送り」に移し、理由を一言残す

### テンプレート

```markdown
### シナリオ名（例: スマホでメールを受信する）

- 追加日: YYYY-MM-DD
- ピンとこない点: 何が繋がらないのか、どこでモヤっとするのか
- 関わりそうなレイヤー: 例）アプリ / トランスポート / ネットワーク / データリンク / 物理 / ハードウェア
- 関わりそうな技術・用語: 例）IMAP, TLS, DNS MX レコード
- 代替技術・比較したいもの: 例）IMAP と POP3、MQTT と CoAP
- 「分かった」と言える状態: これが見えたら納得できる、という具体例
- メモ: 参考リンク、思いつきなど
```

## 採用済み

### ブラウザで URL を開く

- 採用: 第1サイクル（2026年11月末〜2027年3月末）
- ピンとこない点: DNS、TCP、TLS、HTTP、ルーティング、メモリや CPU などの個々の用語は知っているが、URL を開いてから画面が出るまでにそれらがどう組み合わさっているのかが繋がらない
- 関わりそうなレイヤー: アプリケーション〜物理、ハードウェアまで全体
- 「分かった」と言える状態: ある瞬間で時間を止めたまま、虫眼鏡式ズーム（＋で低レイヤー、−で高レイヤー）で各レイヤーが何をしているかを見られる
