# Discovery: ブラウザで URL を開く

- 実施: 2026-11-25〜26（そた + Claude、Example Mapping）
- シナリオ: [features/open-url.feature](../../features/open-url.feature)
- 元の候補: [scenario-backlog.md](../scenario-backlog.md) の「採用済み」

## 🟨 ストーリー

1〜5年目のIT社員として、URL を開いてから画面が出るまでを1ステップずつ進めたり戻したりしたい。それぞれの瞬間に何が起きているかを図で確かめるため。

## 前提

- ユーザーが URL をクリックしたところから始まる（「送信」は段階に含めない）
- HTTP/1.1 を想定する
- 例として `https://example.com` を開く

## 🟦 ルール

### 今回のスライスで扱う

- **R1** 図は常に表示されている
- **R5** 次へ・前へ・ステップ選択で時間を動かせる
  - **R5-a** ステップは「段階」と、その中の「小ステップ」の2階層。段階は DNS → TCP → TLS → HTTP → 描画
  - **R5-b** 「次へ」は段階の境目もまたいで進む（TCP の最後 → TLS の最初）
  - **R5-c** 最初のステップでは「前へ」、最後のステップでは「次へ」が非活性
- **R2**（入れられれば）部品をクリックするとプロトコル名と概要が出る

### 次のスライス以降

- **R3** 今何をしているかが単語レベルで分かる
- **R4** それがネットワークの何層にあたるかが分かる
- **R6** ＋/− ボタンに加えて、部品（例: 通信中のサーバ）のクリックでも拡大できる

### 決まった方針

- ＋/− は**空間の大きさ**のズーム（＋で1台の中へ、−で AS 間など広い範囲へ）
- プロトコルの層は色分けで表す。多すぎるなら画面上部の選択肢で表示するものを選ぶ
- その瞬間に関係のない部品は、拡大できないか、色を変えて「今は動いていない」と分かるようにする
- ステップを移っても、表示しているのは常に「同じ瞬間」

## 🟩 具体例

| # | ルール | 状況 | 操作 | 結果 |
| --- | --- | --- | --- | --- |
| 1 | R1 | URL を開いた直後 | なし | DNS 段階の最初のステップの図と説明が見える |
| 2 | R5-c | 最初のステップ | なし | 「前へ」が非活性 |
| 3 | R5-c | 描画段階の最後のステップ | なし | 「次へ」が非活性 |
| 4 | R5-b | ステップ選択で「TCP：コネクション確立」を選んだ | 次へ | TLS 段階の最初のステップに進む |
| 5 | 方針 | TCP 3ウェイハンドシェイクで止めている | ＋ | Web サーバの中へ。アプリはまだ何もしていない（リクエスト未着） |
| 6 | 方針 | TCP 3ウェイハンドシェイクで止めている | − | AS 間の通信が見える |

TCP 段階の小ステップ: 3ウェイハンドシェイク → コネクション確立
