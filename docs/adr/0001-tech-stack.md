# 0001. 技術スタック

- ステータス: 採用（バックエンドは未決）
- 日付: 2026-11-26（判断自体は 2026-10-30〜11-04）

## 背景

このアプリはそた自身の学習を兼ねた個人開発で、第1サイクル（2026年11月末〜2027年3月末）で「ブラウザで URL を開く」シナリオを動かすところまで作る。
作ること自体に加えて、実務で使う・使いたい技術に慣れることも目的にしている。

## 決定

- **フロントエンド**: TypeScript + React（Vite）。React と TypeScript は学びたい技術なので選んだ
- **部品づくり**: Storybook。実務で使っていて慣れている
- **テスト**
  - 単体: Vitest
  - E2E / 受け入れ: Playwright + playwright-bdd（`bddgen` で `.feature` からテストを生成）。Playwright は馴染みがあり、BDD の Gherkin をそのまま実行できる
- **公開**: GitHub Pages に静的サイトとして出す（`main` に入ると GitHub Actions で公開）
- **バックエンド**: **未決**。第1サイクルはバックエンドなしの静的サイトで進める。必要になったら Java（経験あり）か Go（学びたい）で決める

## 検討した他の案

- バックエンドを最初から用意する: 第1サイクルの図とステップ送りはフロントだけで描けるので、今は不要と判断
- Cucumber.js で E2E: Playwright のテストランナーやレポートをそのまま使える playwright-bdd を選んだ

## 影響

- サーバーがないので、シナリオのデータは当面フロントに持つ
- バックエンドが必要になる場面（例: 技術を切り替えてシミュレーションする機能）が来たら、この ADR を見直して Java か Go かを決める ADR を足す
