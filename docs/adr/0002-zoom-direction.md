# 0002. ズームの向きと意味

- ステータス: 採用
- 日付: 2026-11-26（最初の判断は 2026-10-30、Discovery で 2026-11-26 に具体化）

## 背景

着想はたまごっちの拡大縮小（体内の細菌から地球規模まで）。ある瞬間で時間を止めたまま、虫眼鏡のようにズームして各所で何が起きているかを見せたい。
ここで「＋/− が何を意味するのか」を決めておかないと、画面ごとに解釈がぶれる。

## 決定

- 虫眼鏡式のズームにする。**＋で細かく、−で広く**
- ＋/− は**空間の大きさ**のズームとする。＋で1台の中（例: Web サーバの中、OS や CPU）へ、−で AS 間など広い範囲へ
- 結果として、＋に進むほど低レイヤー寄り、−に進むほど広域・高レイヤー寄りのものが見える
- プロトコルの層（アプリ / トランスポート / ネットワークなど）はズームではなく**色分け**で表す。多すぎるときは画面上部の選択肢で表示する層を選ぶ
- ステップを移っても、表示しているのは常に「同じ瞬間」。その瞬間に関係ない部品は拡大できないか、色を変えて「今は動いていない」と分かるようにする

## 検討した他の案

- ＋/− をそのままプロトコルの層の上下に対応させる（2026-10-30 の最初の案「＋で低レイヤー、−で高レイヤー」）: Discovery で例を出すと、サーバの中に入るのと AS 間を見るのは「層」より「範囲の広さ」の話だと分かったため、空間のズームに整理し直し、層は色分けに分けた
- ＋と−の向きを逆にする: 地図アプリなどの「＋で拡大」と揃えたほうが迷わないので今の向きにした

## 影響

- 使ってみて向きに違和感があれば入れ替える（2026-10-30 時点でそう決めている）。そのときはこの ADR を置き換える
- 未解決: ＋で見せたいのは「アプリの処理」か「OS も含めた CPU の仕事」か（[Discovery](../discovery/open-url.md) の疑問）
